# T-003: Supabase 프로젝트 생성 및 환경변수(.env) 연결

> 문서 기준 backlog 스냅샷: 최신 sourceHash 미확인 (접근 제한), 이 태스크의 현재 status: **done**
> (이 문서가 존재한다고 해서 이 태스크의 실제 개발이 끝난 것은 아닙니다.)

## 목적

개발요청서.md의 E. 플랫폼 섹션 "기술 스택: Supabase(Postgres/Auth/Realtime/Storage) + ... 개발자 재량"에 따라, Supabase를 실시간 백엔드로 선택하고 프로젝트를 생성하여 환경변수와 연결합니다.

## 쉬운 설명

Supabase (Firebase의 오픈소스 대안)에서 새로운 프로젝트를 만들고, 데이터베이스(Postgres), 인증, 실시간 기능 등에 접근하기 위한 URL과 키를 `.env.local`에 설정합니다.

## 필요한 입력

- Supabase 계정 (supabase.com)
- 프로젝트 생성 권한
- 조직/팀 설정 (원하는 경우)

## 결과물

- Supabase 프로젝트 (예: 프로젝트명-supabase-projectid)
- `.env.local`에 추가된 환경변수:
  - `NEXT_PUBLIC_SUPABASE_URL`
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
  - 선택사항: `SUPABASE_SERVICE_ROLE_KEY` (서버 전용)
- `@supabase/supabase-js` 또는 `@supabase/ssr` 라이브러리 설치

## 선행 작업

- T-001 (Next.js 프로젝트)

## 수행 순서 (권장)

1. supabase.com에서 "새 프로젝트" 생성
2. 프로젝트명, 지역(Region) 선택 (한국 권장: Singapore 또는 Tokyo)
3. 데이터베이스 암호 설정
4. 프로젝트 생성 대기
5. "Settings" → "API"에서 URL과 `anon public key` 복사
6. `.env.local`에 붙여넣기
7. `npm install @supabase/supabase-js` (또는 `@supabase/ssr`)
8. 간단한 테스트 쿼리 실행 (예: `supabase.auth.getUser()`)

## done_when 확인 방법

- Supabase 대시보드에서 프로젝트가 "Active" 상태인가?
- `.env.local`에 URL과 키가 설정되어 있는가?
- `npm run dev` 실행 시 Supabase 클라이언트가 초기화되는가 (콘솔 에러 없음)?
- 샘플 쿼리(예: `supabase.from('...').select()`)가 작동하는가?

## 확인 질문

- Supabase의 기본 region 선택과 미래의 확장성 고려 사항은 개발요청서에 명시되지 않았습니다.
